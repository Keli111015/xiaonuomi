# 摄像头预览与坐姿调试工具

2026-10-31 按修复后的脚本更新。配合支持 JPG2 的固件使用，旧 `JPEG <n>` 裸数据协议不兼容；源码修复及验证范围见[项目交接](../../docs/CURRENT_HANDOFF.md)，当前固件尚未编译或实测。

## 启动

从项目根目录执行。以下仅为用法，本轮不启动服务、不连接串口：

```powershell
python -m pip install -r tools/camera/requirements.txt
python tools/camera/reliable_preview.py
```

浏览器打开 `http://127.0.0.1:8765`。当前 `reliable_preview.py` 的 `uart.port` 写死为 **COM4**，波特率 115200；使用前编辑为实际串口。脚本**没有 `--port` 参数**，也不自动查找设备。不要同时开启 miniterm、IDF monitor 或其他占用同一串口的程序。

脚本会开启取流并请求串口抓拍，不是只读日志查看器。关闭网页不会结束 Python 服务；使用 `Ctrl+C` 结束进程并释放串口后再进行其他设备操作。

## 预览与协议

- JPG2 按帧编号和偏移重组 Base64 数据，验证长度及 FNV-1a，检错不等于安全认证。
- 串口抓拍不是流畅视频；旧画面会变淡，不能用重复旧帧当成实时识别。
- 图片在本机显示，不持续录制；工具本身不上传图片。该说明不代表完整应用的云端语音链路离线运行。
- 识别日志在本地写入，应避免提交设备信息、照片和原始日志。

## 坐姿与校准限制

先固定摄像头，选择人物正立的方向，确保单人的脸、双眼、双肩完整入镜。有效基准为 RAM 状态，重启或改变识别方向会清空；改变相机位置、距离或使用者后旧基准不再可靠。

网页“坐正校准”先发送一次 `cam calibrate`，随后最多两次 `cam pose`。修复后的固件在成功取帧的 calibrate 请求中重置基准，由分析器单帧至多加一次样本；无效或不稳定样本不能完成校准。Python 请求顺序与失败提示已测试，实际设备采样和重校准仍需验收；使用旧固件时不适用这一语义。

可通过串口 `cam pose <方向>` 观察自动校准与推理日志；完整机制、HP 接入和验收边界见[坐姿识别](../../docs/POSE_RECOGNITION.md)。该模块已存在接入学习队列的代码，不能再声称绝不触发自动扣血；实际行为还取决于设备固件和专注状态。真人准确率未验收。

## 测试

`test_frame_protocol.py` 测试帧协议，`test_preview_detection.py` 提取实际预览函数并模拟板端返回值，验证校准请求顺序、重校准及失败提示。两者不导入串口模块、不连接硬件；从项目根目录运行：

```powershell
python -m unittest discover -s tools/camera -p "test_*.py"
```

本轮共 10 项通过。`tools/tests/` 下的姿态、舵机、语音 guard 测试会调用 C/C++ 编译器，详见[测试说明](../tests/README.md)，禁止编译时不能运行。
