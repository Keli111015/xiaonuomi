# 实验性坐姿识别

2026-10-31 依据修复后的 SDK 静态核对。真人坐姿准确率尚未验收，不能把姿态异常当成可靠的分心判定。本轮运行了纯 Python 预览请求及协议测试，没有编译 C/C++、运行模型或连接摄像头。

## 当前处理链路

`BF3901 → 摄像头帧服务 → vision_service → UYVY 转 RGB / 旋转 → YOLO11 关键点 → 质量门控及相对基准分类 → 学习事件队列`。

- 相机输入为 240×320 UYVY；方向可设为 0 / 90 / 180 / 270。
- 关键点质量不足、未完成基准、无可靠单人结果等应按 UNKNOWN 处理，不将离开画面算作走神。
- 识别规则使用眼睛、鼻子、肩膀的几何关系，比较相对倾斜、靠近和低头；不是专门重训的坐姿模型，也不是人体工学诊断。
- `vision_service.c` 已将结果提交到 `morphcube_study_runtime_submit_pose()`；旧说明“未接入 HP 队列”已过时。
- 专注时每 10 秒请求一次，语音忙或相机不可用时跳过并记录日志；串口预览与检测不等于流畅实时视频。

## 校准语义

基准在 RAM，重启或视觉服务处理方向变化时清空。固定相机、单人坐正并确保脸、双眼、双肩完整入镜是必要前提；相机、距离或使用者变化后原基准可能失效，尚无身份跟踪。

当前仅 `yolo11_pose.cpp` 的分析器在未校准且质量门控通过、绝对阈值看起来基本端正时增加样本，每帧至多一次；视觉服务不再二次 add。三个稳定、有效样本完成基准后冻结，普通 pose 不更改已完成基准。

`cam calibrate <方向>` 在成功获取帧后显式 reset，再分析该帧。后续用 `cam pose <方向>` 继续采样；不要每张图片都发送 calibrate，否则每次都会重新开始。成功取帧后的方向变化也会 reset；取帧失败不改变已有基准，并向学习队列报告 UNKNOWN。

网页按钮发送一次 calibrate，再最多两次 pose。无效帧或不稳定样本不会被按钮当作完成；本轮已用模拟返回值验证实际 Python 请求函数的顺序与提示，未验证设备端样本和模型。

## 异常累计和 HP

SDK 状态机允许相邻有效异常结果最多 25 秒间隔，按实际时间累计并封顶 15 秒，提醒冷却 60 秒。正常、UNKNOWN、暂停/停用、超时断档或时钟倒退会清空累计。

自动采样每 10 秒一次，理想情况下第三个异常样本、首帧后约 20 秒达到门槛；跳过和推理时延会改变时序。该规则表示异常样本链覆盖时间，不证明未采样期间持续异常，也不是“连续低头 15 秒即提醒”的实测保证。

达到提醒门槛后当前状态机扣 5 HP，播放受伤或耗尽音效，耗尽时结束本轮番茄钟。这是当前代码事实，但“低头写字不应直接当作分心处罚”的产品要求仍需与实现对齐。详细 HP 规则见[学习规则](STUDY_RUNTIME.md)。
