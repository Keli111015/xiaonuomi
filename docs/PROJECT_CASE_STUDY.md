# 小诺米：项目实践复盘

[返回项目首页](../README.md)

## 背景与目标

小诺米 / Lil Noémie 是一个面向学习和日常陪伴的桌面机器人团队项目。产品从 MorphCube 学习伙伴方案演进而来，逐步形成语音陪伴、专注反馈、坐姿实验和结束摆头的交互组合。

目标是建立一个能理解请求、维护学习状态并通过声音和动作作出反馈的硬件原型。当前仓库包含应用源码、SDK 依赖、模型和主机测试；海报用于表达外观设定，实物仍处于整机验证阶段。

## 关键问题与设计取舍

### 1. 如何避免“说开始了，设备却没有开始”

语音会话、云端业务和设备计时属于不同环节。项目使用平台产品方法接入设备，板端收到方法后调用本地计时器；跨板时额外等待动作板的执行结果 ACK。

这样可以分别观察“命令已入队”“远端已执行”和“实际机械动作”。当前 ACK 已有实机验证，但还没有作为 Agent 的口头确认依据；把远端结果进一步反馈给用户是下一步改进。

实现入口：[方法接入](../sdk/apps/main/lj_components/pomodoro/pomodoro.c)、[板间桥接](../sdk/apps/main/lj_components/pomodoro/board_bridge.c)。

### 2. 多种结束原因如何统一触发动作

自然结束、用户停止与 HP 耗尽会经过不同的番茄钟事件。项目把这些路径收敛到学习运行时的提醒入口，由同一任务维护本轮提醒标记，只有请求成功接受后才记为已提醒。

新一轮进入 FOCUS 时清除标记；FINISHED 等后续事件不会重复触发，空闲 stop、休息结束和阶段 skip 也不会误触发。舵机忙时返回错误，当前没有动作排队保证。

实现入口：[学习运行时](../sdk/apps/main/lj_components/morphcube/morphcube_study_runtime.c)、[舵机驱动](../sdk/apps/main/peripheral/bsp_servo.c)。

### 3. 无线重试如何避免重复执行

协议使用 session、seq 和指令类型识别请求，动作板保存最近请求及其执行结果。重复请求返回原 ACK，过期序号被拒绝；发送端最多尝试三次，并允许新意图替换尚未确认的旧指令。

这提供了有界的重试与诊断能力。去重状态保存在 RAM，重启后不提供“恰好执行一次”保证；两板也未实现精确计时同步。

协议与测试：[双板说明](BOARD_BRIDGE.md)、[主机模拟测试](../tools/tests/test_board_bridge.py)。

### 4. 坐姿识别如何面对个体差异与不完整画面

使用已有 YOLO11 姿态模型获取关键点，再以多帧相对基准判断倾斜、低头等情况。无人物、关键点不足或校准无效时保留未知状态，避免强行分类。

专注期间按周期请求推理。异常样本按单调时间累计，正常、未知或间隔过大时重置；抽样之间没有被观察到的姿态不能直接作为持续异常的证据。主机测试可以验证规则边界，真实准确率仍需采集数据后评估。

实现入口：[姿态接口](../sdk/apps/main/pose/yolo11_pose.h)、[学习规则](STUDY_RUNTIME.md)。

### 5. 如何区分软件联通与整机可用

调试按层检查：平台方法 → 板间传输与 ACK → 本地事件 → PWM 配置与引脚电平 → 舵机实际运动。

历史测试中曾出现执行回执成功、GPIO6 有 PWM 跳变，但舵机仍完全不动的现象。因此当前保留供电、接触与舵机本体的排查项，实际转动作为独立验收条件；不能仅凭日志宣称硬件效果完成。

实现入口：[结束提醒与诊断](FOCUS_SERVO_REMINDER.md)。

## 项目经历概述（团队项目）

> 小诺米 / Lil Noémie：基于 ESP32-S3 的桌面 AI 陪伴机器人。项目围绕“语音请求—专注状态—多模态反馈”组织产品交互，接入 Agora 云端语音与 MQTT 产品方法，实现番茄钟、100 HP 专注反馈和本地姿态检测。通过 FreeRTOS 任务与队列统一维护学习状态，使用加密 ESP-NOW 连接语音板和动作板，并为结束提醒加入事件去重、角度约束与渐变控制。仓库提供构建配置模板、主机回归测试和硬件联调说明，持续推进供电、装配与整机体验验收。

以上概述描述团队项目的实现范围，具体个人贡献对应仓库[提交记录](https://github.com/Keli111015/xiaonuomi/commits/main/)与 [Pull Requests](https://github.com/Keli111015/xiaonuomi/pulls)。
