# 旧产品语音板控制新产品动作板

分工：旧板PID11778，STA MAC68:ee:8f:44:bd:30；新板PID11932，STA MAC68:ee:8f:44:b1:0c。产品配置独立，设备身份不复制。

通信路径：旧板收到云端pomodoro方法 → 转发start/pause/resume/stop意图 → ESP-NOW加密单播 → 新板本地执行 → 执行接口返回值ACK。旧板继续执行本地原有番茄钟逻辑。新板执行入口不再次转发，避免循环。不是语音或对话记录同步。

两块板必须更新代码并部署相同配对密钥。私有board_bridge_local.h被Git忽略；没有私有文件时通信默认关闭。仅两块已配置MAC参与，LMK/PMK随机生成，切勿将密钥或含密钥的固件上传公共仓库。

两块需已连同一个热点的同一2.4GHz信道；同SSID但多AP不同信道不保证通信。peer.channel=0跟随各自当前Wi-Fi信道。网络连接后初始化通信，日志应显示ready role=voice/action encrypted。不是平台跨产品指令广播。

最多发送3次，等待应用ACK间隔2秒。重复session+seq返回原结果而不再次执行；旧序号拒绝。较新的用户意图会替换尚未确认的旧意图。设备重启后内存去重记录会丢失，不提供跨掉电的恰好一次保证。

ACK仅表示本地番茄钟执行接口结果，舵机没有物理位置反馈。超时表示结果未知，不等于确定没执行；目前远端执行结果仅记在旧板日志，未反馈成Agent的口头确认。发送ACK丢失可能实际已经执行。

先一起启动专注，再停止专注，动作板才能在FOCUS→STOPPED时摆头；只向闲置板发送stop不会摆头。手动开始后两板分别计时，不是精确时钟同步。

已验证：真实桥接工作任务的离线模拟测试覆盖加密peer设置、重复执行抑制、3次重试上限、新指令顺序、过期序号拒绝；固件完整编译。双板无线互通、真实语音下发与舵机联动待两块板同时到场验证。

测试入口：python tools/tests/test_board_bridge.py --cc <gcc路径>。
